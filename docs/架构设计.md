# nginx-app - 架构设计

## 架构职责

提供宿主机 Nginx 的域名入口和反向代理。论文系统本身的前端、后端和 MySQL 仍由 `erp-settlement-thesis` 项目的 Docker Compose 管理。

## 当前网络拓扑

```text
Internet
   |
   | erp.lytt.fun:80
   v
宿主机 Nginx
   |
   | 301 -> HTTPS
   v
宿主机 Nginx:443
   |
   | 127.0.0.1:8080
   v
erp-settlement-prod-frontend
   |
   | /api/ -> backend:3000
   v
erp-settlement-prod-backend -> mysql:3306
```

前端端口只绑定到宿主机回环地址，因此后端和数据库不会直接暴露到公网。Nginx 不需要加入 Docker 网络，也不需要知道 `backend` 容器的地址。

## 路由规则

| 域名 | 上游 | 说明 |
| --- | --- | --- |
| `http://erp.lytt.fun` | `https://erp.lytt.fun` | 强制跳转 HTTPS |
| `https://erp.lytt.fun` | `http://127.0.0.1:8080` | 论文系统前端及其 `/api/` 代理 |

新增域名时，在 `conf.d/` 增加独立的 `*.conf` 文件，并让该文件只负责一个域名。修改后必须执行：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

## 发布原则

GitHub Actions 只发布 Nginx 配置，不启动或重建应用容器。发布过程会先备份当前配置，再校验并 reload；校验或 reload 失败时恢复上一版。

## HTTPS

生产配置保存在 `conf.d/nginx.conf`。证书由 Certbot 管理，续期后只 reload Nginx，不重启论文应用。申请证书前使用 `conf.d/nginx-http.conf.example` 临时接管 80 端口。
