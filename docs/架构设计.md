# nginx-app - 架构设计

## 架构职责

本仓库是服务器级共享 Nginx 网关。它提供多个域名的入口、HTTP/HTTPS 路由、ACME 挑战、健康检查和配置回滚；不负责业务镜像、容器、数据库或应用内部网络。

每个应用仓库只需要把对外前端绑定到宿主机回环地址，例如：

```text
应用 A -> 127.0.0.1:8080
应用 B -> 127.0.0.1:8090
             |
             v
        宿主机 Nginx
        |-- a.example.com -> 127.0.0.1:8080
        `-- b.example.com -> 127.0.0.1:8090
```

当前 `erp.lytt.fun -> 127.0.0.1:8080` 只是站点清单中的一个实例，论文仓库继续独立管理前后端和 MySQL。

## 配置分层

```text
config/gateway.env                    网关级公共参数
config/sites/*.env                    一个项目一个站点描述
config/templates/*.template            所有站点共用的 Nginx 行为
scripts/lib/gateway-common.sh          统一默认值和校验
scripts/render-config.sh               本地/Runner 渲染器
scripts/deploy-host-nginx.sh           服务器发布入口
```

渲染器和服务器入口使用同一个共享校验库，避免“Runner 能通过、服务器重新解释失败”的配置漂移。每个站点最终安装为 `/etc/nginx/conf.d/<SITE_CONFIG_FILE>`，受管文件名记录在 `.nginx-gateway-managed` 中。

## 发布流程

```text
Git Tag
  -> GitHub Actions 加载公共配置和站点清单
  -> 渲染生产配置与 ACME bootstrap 配置
  -> Runner 内 Nginx 语法检查
  -> 上传完整发布包
  -> 服务器备份当前受管站点
  -> 缺证书站点申请证书
  -> 原子替换、nginx -t、reload
  -> 逐站点健康检查
  -> 失败恢复上一版站点集合
```

新增项目只增加 `config/sites/<name>.env`，不增加 workflow、systemd timer 或部署脚本。删除站点时由发布清单移除对应受管配置，证书默认保留。

## HTTPS 和续期

所有站点共用 `/var/www/nginx-gateway/acme` 作为 ACME Webroot，证书仍由 Certbot 按域名保存在 `/etc/letsencrypt/live/<domain>/`。服务器只维护一个 `nginx-gateway-certbot-renew.timer`；证书续期成功后执行 Nginx reload，不重启任何应用容器。
